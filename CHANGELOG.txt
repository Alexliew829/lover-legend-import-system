V9.9 Stable — V9.2 Sync Baseline + Sales Card Atomic Inventory

1. Rebuilt directly from the proven V9.2 perfect-running baseline; normal Pull/Push/bootstrap sync flow remains V9.2 structure.
2. One Sales/Fair/Live sales card (transactionId) is one All-or-Nothing inventory transaction.
3. Every product is prechecked before any write. One failure = 0 Products / 0 Imports / 0 Batches / 0 History / no reminder completion.
4. Revision conflict stops the whole card before writes.
5. Cloud write is verified against final Products stock, Imports remaining, Batches remaining, and each product History/Sales link.
6. Any write/verification/revision failure attempts rollback to the pre-transaction snapshot.
7. Sales reminder is completed only after the whole Import transaction succeeds and Sales confirms the whole transactionId.
8. If Import already committed but Sales acknowledgement fails, reminder stays and retry only resends Sales confirmation; inventory is never deducted twice.
9. Manual inventory edits no longer consume Sales pending reminders; reminders are completed only through the whole-card button.
10. Non-inventory Sales changes cannot cause a second deduction when the same Sales links are already fully processed.
11. Source labels: Sales · Belimbing; Sales · Fair · location; Sales · Live · host.
12. FIFO algorithm, average-cost logic, inventory truth rules, History definitions and Google Sheet schema are unchanged.
13. All active frontend/backend/cache/version labels updated to V9.9.
